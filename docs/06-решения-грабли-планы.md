# 06. Решения, грабли и планы

## Почему сделано так

| Решение | Почему |
|---|---|
| Один `search.py` на API, бот и агента | поведение фильтров не расходится; тесты один раз |
| Статус хранится по источнику, у события «самый тревожный» | одна выгрузка не затирает отмену из другого источника; ручная правка ложится на все |
| Даты в местном времени без часового пояса | регион без перехода на летнее время; не путаемся с UTC в карточках |
| Gemini получает инструменты, а не всю базу | ответ строится на фактах из поиска; `event_ids` проверяются на сервере |
| Всегда есть режим правил | демо не падает без ключа, сети, при отказе модели и исчерпании бюджета |
| Агент не выдумывает: «в источнике нет описания» | доверие продукта; в промпте запрещено додумывать сюжет, жанр, участников |
| Tailwind CSS, собранный файл в репозитории | стили описываются утилитами в разметке, токены в одном конфиге; сборка нужна только разработчику (Node), на сервере и в Docker её нет; никакого CDN и рантайм-компилятора: CSP остаётся строгой, а страница грузит один файл около 60 КБ. JavaScript без сборщика |
| Размытие фона только у шапки и панелей чата | на десятках карточек оно давало рывки анимации; полупрозрачная заливка выглядит так же |
| Анимации только `transform`/`opacity` | считаются видеокартой; замер: кадры ~6 мс, ни одного провала |
| Бот пускает только подписчиков, при ошибке проверки не пускает | условие обязательное; «открыть при сбое» превратило бы его в необязательное |
| Контейнеры с `--network host` | иначе они не видят туннель на `127.0.0.1:10809` |
| Загрузчик останавливается, если `robots.txt` недоступен, и не обходит капчу, 403, 429 | уважаем правила сайтов; Ticketland отвечает ботам 403, поэтому не подключён |
| Яндекс Афиша: сеансы из Apollo-состояния страницы, а не из JSON-LD | в JSON-LD записан период показа в UTC, по нему время сеанса неверно (проверено на реальных страницах) |
| Kassir.ru: время «как написано», смещение игнорируется | сайт ставит ложную метку UTC; сверено с текстом страницы («начало в 13:00») |
| Разные даты одной страницы получают разные адреса (`url#дата`) | иначе дедупликация «тот же адрес = то же событие» склеила бы разные дни |
| Аудит дубликатов отдельно от приёма, слияние только по `--apply` | при приёме порог строгий (0,82), чтобы не склеить разные события; мягкий порог (0,72) безопасен только при проверке |

## Грабли окружения (на которые уже наступили)

* **Gemini**: ключ с ограничением API давал `403 API_KEY_SERVICE_BLOCKED` (создан новый). `gemini-flash-latest` отвечал 404, `gemini-2.5-flash` недоступен новым ключам, `3.7/3.8-flash` отвечали 504; рабочая `gemini-3.5-flash`. Иногда 503 «high demand»: временно, ответ уйдёт по правилам.
* **Туннель** многократно обрывался («Connection reset», код 255): нужен цикл с автопереподключением, и он всё равно зависит от компьютера.
* **Windows/Git Bash**: `tar czf C:/…` трактует `C:` как хост; `python` может быть заглушкой Store; PowerShell → `ssh bash -s` добавляет BOM и `\r`; `curl` без `--noproxy '*'` обрезает ответы через локальный прокси.
* **culture.ru** с сервера недоступен по `robots.txt`, с компьютера бывает недоступен совсем (таймауты рукопожатия, 503): подождать и повторить.
* **Telegram**: проверка подписки работает, только если бот администратор канала. Telegram кэширует мини-приложение: после обновления закрыть и открыть заново.
* **Тесты и окружение**: рабочий `.env` не должен влиять на тесты (`conftest.py` очищает токены и ключи).
* **CSP**: встроенные скрипты запрещены; вернёте `<script>…</script>` в страницу — она молча сломается (есть тест).
* **Старые версии**: кнопки бота под давно отправленными сообщениями могут слать устаревшие данные: бот отвечает «кнопка устарела».

## Известные ограничения продукта

* Источники: culture.ru, Яндекс Афиша, Kassir.ru, KudaGo (адаптер готов, но kudago.com из России бывает недоступен и вживую не проверялся), плюс любые сайты из `data/sources.json`. Не подключены: Ticketland (403 ботам), Афиша.ру (нужен разбор страниц дат), официальные сайты театров (нет подтверждённо рабочих адресов).
* Яндекс Афиша: время сеанса известно для даты, которую страница показывает первой, для остальных берётся то же время (если у известных сеансов оно одинаково), иначе только день. Города кроме Уфы (Стерлитамак и др.) заданы списком адресов и не проверены вживую.
* Условия использования данных Яндекс Афиши, Kassir.ru и других сайтов стоит уточнить до публичного запуска: robots.txt их разрешает, но это не то же самое, что разрешение владельца.
* В карточке culture.ru только ближайший сеанс; статусов и описаний нет, поэтому отмены из этого источника не приходят.
* События, пропавшие из источника, сами не удаляются и не помечаются отменёнными.
* Автоматического обновления данных нет.
* Поиск текстовый (`LIKE` по нормализованному тексту), без морфологии кроме грубой обрезки окончаний.
* PostgreSQL не проверялся (код на SQLAlchemy, но боевой путь только SQLite).
* Состояние бота и история чата в браузере: в памяти процесса и в `localStorage`, без аккаунтов.
* Живой Gemini не покрыт автотестами.

## Что делать дальше (по убыванию пользы)

1. **Зарубежный VPS** и переезд всего приложения: убирает туннель, зависимость от домашнего компьютера, побочный риск для чужого проекта.
2. **Регулярное обновление данных**: расписание (cron/планировщик) на машине, откуда доступен culture.ru, или переезд на VPS с доступом к источнику; плюс пометка пропавших событий.
3. **Ещё источники**: сайты театров и филармонии, данные министерства. Статусы отмен приходят именно оттуда.
4. **Внешний мониторинг**: проверка `/api/health`, бота и сертификата с оповещением в Telegram.
5. **Подписка для мини-приложения**: проверять `initData` Telegram на сервере.
6. **Роли и журнал** для админ-методов; вынос лимитов в Redis, если экземпляров станет несколько.
7. **Журнал запросов к ИИ** (что спросили, что ответили, сработала ли подмена на правила) для разбора качества.
8. Юридическая сверка условий использования данных culture.ru.
