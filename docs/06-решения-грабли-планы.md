# 06. Решения, грабли и планы

## Почему сделано так

| Решение | Почему |
|---|---|
| Один `search.py` на API, бот и агента | поведение фильтров не расходится; тесты один раз |
| Статус хранится по источнику, у события «самый тревожный» | одна выгрузка не затирает отмену из другого источника; ручная правка ложится на все |
| Даты в местном времени без часового пояса | регион без перехода на летнее время; не путаемся с UTC в карточках |
| Gemini получает инструменты, а не всю базу | ответ строится на фактах из поиска; `event_ids` проверяются на сервере |
| Всегда есть режим правил | демо не падает без ключа, сети, при отказе модели и исчерпании бюджета |
| Агент предлагает действия, а не выполняет | подписку, перенос и заявку подтверждает человек кнопкой: ни просьба в чате, ни фраза в описании события данных не меняют |
| Метрики считаются прогоном по базе (`eval/`) | «агент хорошо отвечает» проверяется числами: условия против карточек, названия против базы, токены из трассы |
| Незнакомое слово запроса ищется, а не отбрасывается | иначе «концерт Земфиры» молча превращался в любые концерты; не нашлось — так и сказано |
| Исправление агента сжигает отложенные запросы | после правки по их результатам они уже не показывают обобщение: нужны новые внешние |
| Агент не выдумывает: «в источнике нет описания» | доверие продукта; в промпте запрещено додумывать сюжет, жанр, участников |
| Tailwind CSS, собранный файл в репозитории | стили описываются утилитами в разметке, токены в одном конфиге; сборка нужна только разработчику (Node), на сервере и в Docker её нет; никакого CDN и рантайм-компилятора: CSP остаётся строгой, а страница грузит один файл около 60 КБ. JavaScript без сборщика |
| Размытие фона только у шапки и панелей чата | на десятках карточек оно давало рывки анимации; полупрозрачная заливка выглядит так же |
| Анимации только `transform`/`opacity` | считаются видеокартой; замер: кадры ~6 мс, ни одного провала |
| Бот пускает только подписчиков, при ошибке проверки не пускает | условие обязательное; «открыть при сбое» превратило бы его в необязательное |
| Контейнеры с `--network host` | иначе они не видят туннель на `127.0.0.1:10809` |
| Загрузчик останавливается, если `robots.txt` недоступен, и не обходит капчу, 403, 429 | уважаем правила сайтов; Ticketland отвечает ботам 403, поэтому не подключён |
| Яндекс Афиша: сеансы из Apollo-состояния страницы, а не из JSON-LD | в JSON-LD записан период показа в UTC, по нему время сеанса неверно (проверено на реальных страницах) |
| Kassir.ru: время «как написано», смещение игнорируется | сайт ставит ложную метку UTC; сверено с текстом страницы («начало в 13:00») |
| Разные даты одной страницы получают разные адреса (`url#дата`) | иначе дедупликация «тот же адрес = то же событие» склеила бы разные дни |
| Аудит дубликатов отдельно от приёма, слияние только по `--apply` | при приёме порог строгий (0,82), чтобы не склеить разные события; мягкий порог (0,72) безопасен только при проверке |
| Период у театра и концертов Kassir.ru хранится как серия (`series_until`), а не как `end_at` | источник не сообщает сеансов между первой и последней датой; как непрерывное событие серия попадала на любой день периода (спектакль пятницы в запросе про субботу) |
| Схема меняется миграциями Alembic, а не только `add_missing_columns` | в SQLite столбец `age_limit` был `NOT NULL DEFAULT 0`, и «возраст не указан» нельзя было хранить без пересоздания таблицы; Alembic делает это сам (`batch_alter_table`), а старую базу помечает версией `0001` и мигрирует; `add_missing_columns` остался для необязательных столбцов старых баз |
| Генератор выдуманных событий лежит в `tests/demo_data.py`, а не в `app/` | ТЗ §13: выдуманных мероприятий быть не должно; в образ попадает только `app/` |
| Для запуска «с нуля» берётся `data/sample_events.json` с реальными афишами | вместо демо-данных; события, подтверждённые двумя источниками, выгружены двумя записями, чтобы работала склейка |
| Подписки бота хранятся в БД, а рассылку делает сам процесс бота | переживают перезапуск; не чаще раза в сутки и днём, чтобы не быть навязчивым (ТЗ §6.2) |
| Все записи идут через `pipeline.process_record`, а сырая запись сохраняется до слияния | один путь для файлов, парсеров, API и админки; отчёт об импорте, журнал и переигрывание нормализации получаются из одного места |
| Сырые записи хранятся по хешу содержимого (источник + хеш) | повтор той же записи не раздувает таблицу, изменение у источника сохраняется как новая версия |
| `publication` отдельно от `status` | ТЗ называет «опубликовано / черновик / отменено», а у нас ещё «перенесено» и «билеты проданы»: черновик — это видимость, а не состояние события |
| Личные ключи модераторов в `ADMIN_USERS` вместо аккаунтов | журнал «кто что изменил» без базы пользователей и паролей; роли отложены |
| Страница события собирается на сервере в `pages.py`, без Jinja2 | ссылкой можно делиться, есть предпросмотр и schema.org, работает без JavaScript; новая зависимость сломала бы сборку без PyPI (колёса) |
| Старые пути `/api/*` оставлены вторым подключением того же роутера | виджеты и клиенты не ломаются при переходе на `/api/v1` |
| Защита формы без капчи: ловушка, метка времени, лимиты | капча мешает людям, а перечисленные меры отсекают типичных роботов; метки подписаны ключом процесса и после перезапуска просто обновляются |
| Режим без ИИ перечисляет условия, которые не смог проверить | молчаливое игнорирование «после 19:00» или «на башкирском» выдавало бы подборку за точный ответ |
| Возраст «не указан» хранится как NULL, явное «0+» как 0 | иначе фильтр «с ребёнком» считал событие без ограничения подходящим любому возрасту («Макбет» для восьмилетнего); неизвестный возраст пропускается только у явно детских событий |
| Идемпотентность импорта по хешу записи источника | число строк при повторной загрузке совпадало, но 25 записей из двух источников «обновлялись» по кругу, перезаписывая общие поля; теперь та же запись того же источника ничего не меняет |
| Новое событие из источника сначала в очередь, потом проверка | ТЗ §6.5: в публичную выдачу только после проверки; спорное остаётся с причиной (`review_reason`), а не молча публикуется |
| Временный сбой ссылки не «битая ссылка» | culture.ru отвечает роботам 425, Kassir.ru на несуществующую страницу 200: по коду ответа битую ссылку надёжно не узнать, поэтому снимаем с публикации только 404/410 и несуществующий адрес |
| Пропавшие из источника события уходят в очередь, а не удаляются, и только после полного прохода | источник мог упасть или отдать неполный список; решает человек, а вернувшееся событие публикуется само |
| Планировщик ставит только события, начавшиеся в этот день | выставка «с 13 по 30 ноября» находилась поиском по дате, но времени посещения у неё нет (нашли на реальных данных: «экскурсия 10:00–11:30» шла рядом с событием того же времени) |
| Подписки в API подтверждает подпись Mini App, а не номер чата | номер чата из тела запроса позволял бы подписывать и отписывать чужих |
| Системные шрифты вместо Google Fonts | адрес посетителя не уходит третьим сторонам (ТЗ §10); внешний вид почти не меняется |
| Два провайдера модели по цепочке: Gemini (и его запасные модели), потом Groq, потом правила | квота у каждой модели Gemini своя, бесплатные лимиты малы; запасной режим остаётся последним, демо не падает |

## Грабли окружения (на которые уже наступили)

* **Gemini**: ключ с ограничением API давал `403 API_KEY_SERVICE_BLOCKED` (создан новый). `gemini-flash-latest` отвечал 404, `gemini-2.5-flash` недоступен новым ключам; рабочие `gemini-3.5-flash`, `3.5-flash-lite`, `3.1-flash-lite` и новая `gemini-4-hydrogen` (около 28–31 с на ответ с инструментами против 2,5–4 с у `flash-lite`: порог ТЗ 8 с она не проходит). Иногда 503 «high demand» и SSL-ошибки: временно, берётся следующая модель. **Бесплатный ключ даёт 5 запросов в минуту и 20 в сутки на модель**: полный прогон `eval` на нём невозможен, а прогон при исчерпанной квоте смешивал ответы правил с ответами модели (теперь он останавливается и не пишет отчёт).
* **Туннель** многократно обрывался («Connection reset», код 255): нужен цикл с автопереподключением, и он всё равно зависит от компьютера.
* **Windows/Git Bash**: `tar czf C:/…` трактует `C:` как хост; `python` может быть заглушкой Store; PowerShell → `ssh bash -s` добавляет BOM и `\r`; `curl` без `--noproxy '*'` обрезает ответы через локальный прокси.
* **culture.ru** с сервера недоступен по `robots.txt`, с компьютера бывает недоступен совсем (таймауты рукопожатия, 503): подождать и повторить.
* **Telegram**: проверка подписки работает, только если бот администратор канала. Telegram кэширует мини-приложение: после обновления закрыть и открыть заново.
* **Тесты и окружение**: рабочий `.env` не должен влиять на тесты (`conftest.py` очищает токены и ключи).
* **Бесплатный Groq**: 8000 токенов в минуту на модель, ответ агента тянет 5–6 тысяч, поэтому подряд идут примерно один ответ в минуту; `llama-3.3-70b-versatile` аккаунту недоступна, `gpt-oss-120b` иногда отдаёт итог вызовом несуществующего инструмента (ошибка 400).
* **SQLite и NOT NULL**: столбец нельзя сделать необязательным командой `ALTER`; нужна миграция с пересозданием таблицы (Alembic `batch_alter_table`). Проверять миграции на копии базы: `DATABASE_URL=sqlite:///копия.db python -m app.scheduler --list` применит их и ничего не запустит.
* **Тесты и время**: бот и API считают «сейчас» по настоящим часам, поэтому тестовые события заводят относительно `now_local()`, а не фиксированной даты, иначе они «в прошлом» и поиск их не находит.
* **Сервер запущен до правки `.env`**: ключ админки (и любая переменная) читается только при старте процесса; пока не перезапущен, админка отвечает «ADMIN_API_KEY не задан».
* **Docker Desktop** должен быть запущен: тогда `docker compose build` и `docker compose up -d` работают (проверено 13 ноября: сайт отвечает 200 примерно через 8 секунд).
* **CSP**: встроенные скрипты запрещены; вернёте `<script>…</script>` в страницу — она молча сломается (есть тест).
* **Старые версии**: кнопки бота под давно отправленными сообщениями могут слать устаревшие данные: бот отвечает «кнопка устарела».

## Известные ограничения продукта

* Источники: culture.ru, Яндекс Афиша, Kassir.ru, KudaGo (адаптер готов, но kudago.com из России бывает недоступен и вживую не проверялся), плюс любые сайты из `data/sources.json`. Не подключены: Ticketland (403 ботам), Афиша.ру (нужен разбор страниц дат), официальные сайты театров (нет подтверждённо рабочих адресов).
* Яндекс Афиша: время сеанса известно для даты, которую страница показывает первой, для остальных берётся то же время (если у известных сеансов оно одинаково), иначе только день. Города кроме Уфы (Стерлитамак и др.) заданы списком адресов и не проверены вживую.
* Условия использования данных Яндекс Афиши, Kassir.ru и других сайтов стоит уточнить до публичного запуска: robots.txt их разрешает, но это не то же самое, что разрешение владельца.
* В карточке culture.ru только ближайший сеанс; статусов и описаний нет, поэтому отмены из этого источника не приходят.
* События, пропавшие из источника, помечаются и уходят в очередь модерации, но отменёнными не считаются: источник мог их просто убрать. Помета работает после первого прохода (у загруженных ранее событий нет отметки «видели в источнике»).
* Обновление данных по расписанию работает только пока запущен `python -m app.scheduler`; с российского сервера открываются не все источники.
* Правка модератора живёт до следующей синхронизации того же источника: он перезапишет собственные поля.
* Справочник площадок строится из нормализованных названий (`venue_key`): «Дворец молодёжи» и «Дворец Молодежи» объединяются, «ГКЗ «Башкортостан»» и «Государственный концертный зал «Башкортостан»» пока нет.
* Подписки в REST API и на сайте работают только внутри Telegram (подпись Mini App); из обычного браузера подписаться нельзя.
* Планировщик «Выходной день» оценивает дорогу по расстоянию и типичным 20 минутам внутри города, карт и маршрутов нет; выставки и экскурсии «на период» в план не входят.
* Аккаунтов и ролей нет, история посещений не ведётся ([08](08-аккаунты-и-роли.md)).
* Страницы `/admin`, `/feedback` и `/plan` проверялись в браузере вручную, автоматических тестов интерфейса (Playwright) нет; вкладка «Сбор» в админке проверена только через API.
* Поиск текстовый (`LIKE` по нормализованному тексту), без морфологии кроме грубой обрезки окончаний.
* PostgreSQL не проверялся (код на SQLAlchemy, но боевой путь только SQLite).
* Состояние бота и история чата в браузере: в памяти процесса и в `localStorage`, без аккаунтов.
* Живой Gemini не покрыт автотестами.

## Что делать дальше (по убыванию пользы)

1. **Зарубежный VPS** и переезд всего приложения: убирает туннель, зависимость от домашнего компьютера, побочный риск для чужого проекта.
2. **Регулярное обновление данных на постоянной машине**: планировщик уже есть (`app/scheduler.py`), нужен процесс на машине, откуда открываются источники, или переезд на VPS; пометка пропавших событий сделана.
3. **Ещё источники**: сайты театров и филармонии, данные министерства. Статусы отмен приходят именно оттуда.
4. **Внешний мониторинг**: проверка `/api/health`, бота и сертификата с оповещением в Telegram.
5. **Подписка для мини-приложения**: проверять `initData` Telegram на сервере (подпись для API подписок уже проверяется, для доступа к самому сайту нет).
6. **Аккаунты и роли** ([08](08-аккаунты-и-роли.md)): история посещений, организатор, модератор, министерство; вынос лимитов в Redis, если экземпляров станет несколько.
7. **Журнал запросов к ИИ** (что спросили, что ответили, сработала ли подмена на правила) для разбора качества.
8. Юридическая сверка условий использования данных culture.ru.
9. **Метрики качества агента на настоящей модели**: полный прогон `python -m eval.run --mode llm --confirm-spend` на платном ключе, решение по задержке (порог 8 с), 10 внешних запросов от проверяющего.
10. **Отчёт качества §9.1** (полнота карточек, полнота поиска, пустая выдача) и ручная проверка 50 карточек.
