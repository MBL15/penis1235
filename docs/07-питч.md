## 1. Фраза-крючок

> **«Афиша культуры Башкортостана — одно место, где события со всей республики собраны без дублей, с честными статусами отмен и переносов, а подобрать, куда пойти, можно обычной фразой: “в субботу с ребёнком до 1000 рублей”.»**

Ещё короче (для первого слайда): **«Куда пойти в Башкортостане — спросите обычными словами.»**

### Питч за 30 секунд

Культурные события республики разбросаны по десяткам сайтов, дублируются, а об отмене узнаёшь уже у дверей. Мы собрали их в единую базу: реальные данные с culture.ru, склейка дублей, статус у каждого события. Поверх базы работает ИИ-помощник, который понимает запрос обычным языком и отвечает **только фактами из базы**, ничего не выдумывая. Всё это доступно как сайт, Telegram-бот и мини-приложение, а ещё как открытый API и виджет, который министерство ставит на свой сайт одной строкой кода.

## 3. Чем мы отличаемся (то, что можно сказать смело)

1. **Достоверность прежде всего.** ИИ описывает событие только фактами из базы; нет описания, так и говорит: «в источнике нет описания». Рекомендовать он может лишь события, которые реально вернул поиск: выдуманные номера отбрасывает сервер.
2. **Статусы по каждому источнику.** Событие показывает самый тревожный статус из всех источников: одна выгрузка не затрёт отмену, о которой сообщил другой источник.
3. **Не падает.** Нет ключа, нет сети, Gemini перегружен, исчерпан бюджет: ассистент переключается на разбор запроса по правилам и продолжает отвечать.
4. **Везде, где пользователь:** сайт, бот, мини-приложение внутри Telegram, и тот же интерфейс одним стилем.
5. **Открытость.** Документированный REST API (Swagger) и виджет в Shadow DOM: министерство ничего не перестраивает у себя.
6. **Безопасность продумана**, а не «потом»: заголовки CSP, лимиты, бюджет на ИИ, защита от чужих сайтов, контейнеры без root (раздел 9).
7. **Проверяемость:** 163 автотеста, включая бота целиком и подмену Gemini на реальных типах SDK.

## 5. Технологический стек

| Слой | Технологии | Зачем именно так |
|---|---|---|
| Язык | Python 3.12 | одна кодовая база для API, бота и агента |
| Веб/API | **FastAPI**, Uvicorn, Pydantic v2 | автодокументация Swagger/OpenAPI из коробки, строгая проверка данных |
| Данные | **SQLAlchemy 2**, SQLite (PostgreSQL через `DATABASE_URL`) | быстрый старт без инфраструктуры, переезд на PostgreSQL заменой строки |
| ИИ | **Google Gemini** (`gemini-3.5-flash`), вызов функций (function calling), SDK `google-genai` | быстрая модель с инструментами; цикл вызовов ведём сами, чтобы контролировать шаги, время и бюджет |
| Запасной ИИ-режим | собственный разбор запросов регулярками (`rules.py`) | работает без ключа и сети |
| Бот | **aiogram 3**, long polling, `aiohttp-socks` | современный асинхронный фреймворк, прокси для обхода блокировок |
| Мини-приложение | Telegram WebApp API | тот же сайт, перестроенный «как приложение» |
| Фронтенд | **Tailwind CSS** (готовый файл около 60 КБ, без CDN), чистый JavaScript без сборщика; шрифт Inter | стили утилитами в разметке и токены дизайна в одном конфиге; быстро грузится, строгая политика безопасности |
| Дизайн | «матовое стекло» на ярком фоне, индиго-акцент, плитки bento, анимации на `transform`/`opacity` | современный вид; уважает `prefers-reduced-motion` |
| Источник данных | адаптер culture.ru (JSON из `__NEXT_DATA__`), `robots.txt`, паузы, честный User-Agent | реальные данные, этично |
| Деплой | **Docker** (не root, read-only), **nginx** (лимиты), Let's Encrypt, Ubuntu | воспроизводимо, безопасно |
| Тесты | **pytest**, 163 теста | поиск, дедупликация, агент, бот целиком, безопасность |

Объём: около **2 900 строк Python**, 1 500 строк фронтенда, 1 565 строк тестов, 17 модулей.

## 6. Архитектура (для слайда)

```
 culture.ru ─► адаптер ─► нормализация ─► дедупликация ─► БД (events)
 (JSON/CSV/API организаторов)                                │
                                                             ▼
                         ┌───────────── единый поиск (search.py) ─────────────┐
                         ▼                    ▼                      ▼        ▼
                     REST API            ИИ-агент               Telegram-бот  Сайт
                   (+ Swagger,        (Gemini + инструменты;     (+ подписка,  (+ чат,
                    виджет)            запасной режим правил)    мини-апп)     фильтры)
```

Ключевая мысль слайда: **источников может быть сколько угодно, потребителей тоже: посередине один поиск и одна модель данных.** Новый источник — это один адаптер, остальное (нормализация, склейка дублей, статусы) уже работает.

### Как работает ИИ-ответ (для слайда «почему можно доверять»)

1. Пользователь пишет запрос → 2. Gemini переводит его в параметры поиска («в субботу» → даты, «до 1000» → цена) → 3. Поиск по нашей базе → 4. Gemini пишет ответ **только по найденному** → 5. Сервер проверяет, что все упомянутые события реально найдены, и экранирует текст → 6. Пользователь видит ответ и карточки с кнопками.

## 9. Безопасность и надёжность (один слайд)

* Приём данных только по ключу (≥ 24 символов), блокировка подбора, проверка всех полей (только `http(s)`-ссылки, пределы длины и значений).
* Чужие сайты могут только читать; запись с другого сайта запрещена.
* Лимиты: общий на API, отдельный на ИИ, отдельный на каждого пользователя бота; бюджет модели (одновременность, сутки, время ответа).
* Политика безопасности браузера (CSP): встроенные скрипты запрещены, страницу во фрейм открывает только Telegram.
* Контейнеры не от root, файловая система только для чтения, возможности ядра сняты; nginx с лимитами, HTTPS с автопродлением.
* ИИ: только чтение, ответ проверяется и экранируется, инструкции из текстов источников не выполняются.
* Источник: уважаем `robots.txt`, не ходим на посторонние адреса.

## 11. Вопросы жюри и ответы

**«Откуда данные и можно ли им верить?»**
Официальная федеральная афиша culture.ru: события публикуют сами учреждения культуры. Мы не дописываем ничего от себя, а где источник молчит (описание, статус), так и показываем.

**«ИИ же выдумывает. Как вы это решили?»**
Три слоя: модель получает только результаты нашего поиска и промпт запрещает додумывать; сервер проверяет, что все упомянутые события реально найдены; при сбое включается детерминированный режим по правилам. Есть автотесты на отбрасывание выдуманных номеров.

**«А если ИИ недоступен?»**
Ассистент автоматически переходит на разбор по правилам (даты, цена, возраст, город, категория) и честно подписывает «режим без ИИ». Мы проверяли и без ключа, и при ошибках сети.

**«Как вы убираете дубли?»**
Событие считается дублем, если совпадают город и день, время начала различается не более чем на 3 часа, а названия похожи после нормализации. Дневной и вечерний сеансы остаются разными, «Лекция 1» и «Лекция 2» не склеиваются. Пока подключён один источник, на реальных данных склеивать нечего; на демо-данных и в тестах механизм работает.

**«А отмены и переносы откуда, если culture.ru их не отдаёт?»**
Механизм готов: статус хранится по каждому источнику, берётся самый тревожный, меняется через API (по ключу). Отмены придут из источников, где они есть: сайты театров, данные министерства. Это следующий шаг.

**«Как министерство подключится?»**
Одной строкой `<script src=".../widget.js">`: виджет в Shadow DOM не ломает стили их сайта и не требует правок их систем. Либо напрямую через открытый API. Свои данные они присылают в тот же API.

**«Что с масштабированием?»**
Код на SQLAlchemy: переход на PostgreSQL заменой строки подключения. Поиск один на всех потребителей. Лимиты сейчас в памяти одного процесса: при нескольких экземплярах выносим в Redis (это в планах, не сделано).

**«Безопасно ли это?»**
Да, и мы это проверяли: провели полное ревью кода, нашли и закрыли уязвимости, написали тесты на защиту (раздел 9). Честно: входа пользователей и ролей нет, админ-методы закрыты общим ключом.

**«Сколько стоит ИИ и что если запросов станет много?»**
Модель быстрая и недорогая; расход ограничен бюджетом (одновременность, суточный лимит, время ответа), а сверх бюджета отвечает бесплатный режим правил. Сервис не копит очередь и не падает.

**«Что мешает конкурентам сделать то же?»**
Сама афиша повторима. Ценность в качестве данных (дедупликация, статусы, доверие к фактам), открытости (API, виджет) и подключённых источников. Это и есть наша работа дальше.

**«Бизнес-модель?»** (гипотезы, обозначьте как планы)
Госзаказ/партнёрство с министерством как региональная витрина; платное продвижение событий организаторами, явно помеченное; аналитика посещаемости для учреждений; билеты через партнёров.
