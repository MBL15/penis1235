# 05. Безопасность

Чтение афиши открыто всем, а часть возможностей стоит денег (запросы к Gemini) или меняет данные (приём событий). Поэтому защита строится вокруг трёх целей: **данные нельзя испортить, сервис нельзя положить, платную модель нельзя сжечь.**

Весь HTTP-слой защиты в одном файле: `app/security.py`. Подключение: `app.middleware("http")(guard)` в `main.py`.

## Кто и что может

| Кто | Что может |
|---|---|
| Любой посетитель | читать события, задавать вопросы ИИ (в пределах лимитов) |
| Чужой сайт (виджет, министерство) | только читать через браузер (CORS: `GET`); виджет подключается без всяких ключей |
| Держатель `ADMIN_API_KEY` или личного ключа из `ADMIN_USERS` | `/admin`: правка, публикация, импорт, журнал; добавлять события и менять статусы |
| Подписчик `@sz_orenteam` | пользоваться ботом |
| Владелец чата Telegram (подпись Mini App в `X-Telegram-Init-Data`) или вошедший в аккаунт | видеть и менять свои подписки через `/api/v1/subscriptions` |
| Вошедший в аккаунт (`user`, `organizer`) | кабинет `/account`: своя история посещений (только при согласии), сохранённые поиски, свои обращения, экспорт и удаление данных |
| Аккаунт с ролью `moderator` | те же методы `/api/v1/admin/*`, что и ключ, но без выдачи ролей и ключей; в журнале `user:<номер>` |
| Аккаунт с ролью `ministry` | чтение афиши с личным ключом `X-Partner-Key` и своим лимитом, сводка-счётчики; записывать нельзя |

Роли выдаёт только владелец ключа администратора (`ADMIN_API_KEY` или `ADMIN_USERS`). Админ-методы закрыты ключом или аккаунтом-модератором, все действия попадают в журнал изменений. Устройство аккаунтов: [08](08-аккаунты-и-роли.md).

## Угрозы и меры

| Угроза | Мера | Где |
|---|---|---|
| Подбор ключа приёма данных | ключ ≥ 24 символов, иначе приём выключен; после 10 неудач адрес блокируется на минуту (даже верный ключ); сравнение за постоянное время по байтам; не-ASCII даёт 401, а не 500 | `main.require_admin`, `security.auth_limiter` |
| Порча базы через API | `javascript:`/`data:`/относительные ссылки отклоняются (только `http(s)`), пределы длины всех полей, пределы цен (≤ 10 млн) и возраста, нормализация мелких ошибок | `schemas.EventIn` |
| Чужая страница тратит квоту ИИ руками посетителей | CORS только `GET`; изменяющие запросы с `Origin` не нашего сайта или `Sec-Fetch-Site: cross-site` получают 403; curl и парсеры (без `Origin`) проходят | `security.cross_site_write`, `main.py` |
| Сжигание квоты Gemini, перегрузка | 20 вопросов/мин с адреса; бюджет модели (4 одновременно, 3000/сутки, 45 с на ответ); сверх бюджета отвечают правила; в боте 8 вопросов/мин и один одновременно на пользователя | `security.LlmBudget`, `agent.ask`, `bot.on_text` |
| Выкачивание и перегрузка API | 300 запросов/мин с адреса; IPv6 считается подсетью /64; `/api/health` вне лимита; плюс лимиты nginx | `security.api_limiter`, `deploy/nginx-afisha.conf` |
| Подмена адреса через `X-Forwarded-For` | берётся последняя запись (добавленная нашим nginx из `$remote_addr`), левые подделываются клиентом; доверие включено только для loopback или при `TRUST_PROXY=1` | `RateLimiter.client_ip` |
| Огромные и «вечные» запросы | тело ≤ 1 МБ (пачка событий ≤ 5 МБ), без `Content-Length` и с `Transfer-Encoding` — 411, нечисловой `Content-Length` (в том числе «²») — 413; таймауты медленных клиентов в nginx | `security.body_too_large`, nginx |
| Ответ 500 на подобранный ввод (и шум в логах ошибок) | номера событий в схемах и инструментах агента ограничены INTEGER (1…2³¹−1), иначе SQLite падает с `OverflowError`; числа из строк принимаются только из ASCII-цифр (`"²".isdigit()` истинно, а `int("²")` падает): `/event/{id}`, метка формы, поиск пользователей; обязательные поля нельзя очистить правкой (422). Проверено тестами `test_review_fixes.py` | `schemas.AskIn`, `agent_tools.event_id_arg`, `main.event_page`, `feedback.check_token`, `moderation.edit_event` |
| Тяжёлый поиск | запрос ≤ 200 символов и ≤ 8 слов, `offset` ≤ 100 000, ограничены список статусов и длины фильтров | `main.list_events`, `search.py` |
| XSS | CSP: скрипты только свои и `telegram.org`, **встроенные запрещены**, `object-src 'none'`, `base-uri 'self'`; весь динамический HTML экранируется (`esc`), числа через `Number()`, ссылки только `http(s)`; история чата из `localStorage` проходит очистку формы | `security.CSP_*`, `app.js` |
| Встраивание сайта во фрейм чужой страницы | `frame-ancestors`: только сам сайт и Telegram; для API и `/docs` ещё `X-Frame-Options: DENY` | `security.security_headers` |
| Подмена `Host` | `ALLOWED_HOSTS` (если задан) отклоняет чужие имена (400) | `TrustedHostMiddleware` |
| Утечка версий | `Server: nginx` без версии, `--no-server-header` у uvicorn | nginx, Dockerfile |
| Взлом контейнера | не root (uid 1000), `--read-only` (пишет только `/data` и `/tmp`), `--cap-drop ALL`, `no-new-privileges`, лимит памяти и процессов | `deploy/run.sh`, `Dockerfile` |
| Подбор или кража ключа модератора | личные ключи (`ADMIN_USERS`), ключ ≥ 24 символов, сравнение за постоянное время по всем ключам, блокировка после 10 неудач; все действия в журнале под именем владельца ключа; страница `/admin` не индексируется, ключ хранится только в `sessionStorage` вкладки | `auth.py`, `audit.py` |
| Спам в форме обратной связи | поле-ловушка, подписанная метка времени, лимиты (5 в час с адреса и общий), не больше двух ссылок, отсев повторов, запрет чужих POST | `feedback.py`, `security.cross_site_write` |
| Запрос во внутреннюю сеть через ссылку в записи (SSRF) при проверке ссылок | проверяются только `http(s)` на публичные адреса: `localhost`, частные, link-local и метаданные облака отклоняются до запроса, перенаправления проверяются заново, не больше трёх. **Подмена DNS (DNS rebinding):** имя разрешается один раз, соединение открывается именно с проверенным IP (сертификат сверяется с именем хоста), поэтому ответ DNS «уже внутренний адрес» на втором разрешении не срабатывает; прокси окружения не используется (иначе имя разрешал бы прокси). Временные сбои (403, 429, 5xx, таймаут) не снимают событие с публикации | `verify.public_url`, `verify.pinned_connection`, `_CheckedRedirects` |
| Чужие подписки через API | чат определяется подписью Mini App (HMAC-SHA256 от токена бота, не старше суток), номер чата из тела запроса не принимается; чужую подписку не увидеть и не удалить; лимит 30 действий в минуту | `telegram_auth.py`, `api_public.telegram_chat` |
| Подмена стиля виджета через атрибут | `data-height` принимает только число с единицей px, vh, em, rem; остальное игнорируется | `widget.js` |
| Снятие с публикации всей афиши ложной «пропажей» | пустой ответ источника или проход с записями меньше половины лучшего из пяти последних ничего не помечает; пропавшее уходит в очередь, а не удаляется | `vanished.py`, `scheduler.py` |
| Утечка персональных данных через логи | JSON-логи без адресов, строки запроса и текстов; access-лог uvicorn отключён; журнал nginx без адресов (`afisha_noip`) | `observability.py`, nginx |
| XSS на странице события | всё из источников экранируется (`html.escape`), ссылки только `http(s)`, JSON-LD без символа `<`, встроенных скриптов нет | `pages.py` |
| Показ черновика посторонним | черновики исключены из поиска, API, бота, агента и справочников, карточка `/event/{id}` даёт 404 | `search._conditions`, `get_event` |
| Прочтение секретов на сервере | `.env`, `.env.bot`, база: права 600, каталог данных 700; секреты в образ не попадают (`COPY app`, не весь каталог) | `deploy/run.sh` |
| Инъекции через ИИ | просьба раскрыть инструкции или сменить роль отклоняется до обращения к модели; фразы-приказы из описаний событий вырезаются; в промпте метка-ловушка: если она в ответе, ответ заменяется отказом; модель получает только инструменты чтения, а действия (подписка, заявка) лишь предлагает, выполняет человек кнопкой в течение 15 минут и только в своём чате; `event_ids` проверяются на сервере; ответ экранируется везде. 10 кейсов в `eval/queries.json` | `safety.py`, `agent.py`, `agent_actions.py` |
| Инъекции в бот | данные кнопок разбираются строгими регулярками; названия из источников экранируются в HTML; кнопки под исчезнувшим сообщением не роняют бот; сообщения без автора (от имени канала) подписку не проходят | `bot.py` |
| Вредный ответ источника | общий загрузчик `Fetcher`: только HTTPS и разрешённые хосты, перенаправление проверяется **до** перехода (запрос на посторонний или внутренний адрес не уходит), ответ ≤ 8 МБ, `robots.txt` читается перед каждым сайтом, пауза между запросами, капча/403/429 останавливают обход (мы их не обходим). Тексты из разметки очищаются от тегов и сущностей, ссылки только `http(s)` | `sources/base.py`, `sources/jsonld.py` |
| SQL-инъекции | только параметризованные запросы SQLAlchemy; в `LIKE` подставляется нормализованный текст (буквы и цифры) | `search.py`, `normalize.py` |
| Уязвимые зависимости | версии закреплены (`~=`) в `requirements.txt`; на сервере собираются из заранее скачанных колёс | `requirements.txt` |

## Заголовки, которые отдаёт сайт

`Content-Security-Policy` (разная для страниц, `/api/`, `/docs`; шрифты и стили только свои: Google Fonts больше не подключаются), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (геолокация, камера, микрофон, платежи, USB выключены), `Strict-Transport-Security` (по HTTPS), `Cache-Control: no-store` на `/api/ask`. Проверка: `curl -sI https://195-209-220-227.sslip.io/`.

Страница `/docs` (Swagger) требует `unsafe-inline` и CDN `cdn.jsdelivr.net` — это отдельная более мягкая политика только для неё.

## Персональные данные

Без аккаунта хранятся только данные подписок (бот и API): номер чата Telegram и выбранные город и категория (таблица `subscriptions`). Срок хранения: до `/unsubscribe` (в API: `DELETE /api/v1/subscriptions`), но не дольше 12 месяцев с оформления; при блокировке бота подписки стираются сразу.

Если человек сам вошёл в аккаунт, добавляются: номер Telegram и имя оттуда же, роль, согласие на историю с датой (`users`), входы (`user_sessions`, только хеш токена, `SESSION_DAYS` = 30), сохранённые поиски, обращения с привязкой к аккаунту. **История посещений** (`visit_history`: номер карточки, тип, время) пишется только после согласия, хранится 90 дней (`HISTORY_RETENTION_DAYS`), стирается кнопкой «Очистить» и при отзыве согласия. «Скачать мои данные» отдаёт всё перечисленное в JSON, «Удалить аккаунт» стирает пользователя, входы, историю, поиски, подписки (и подписки бота с тем же номером чата), ключи; обращения остаются без автора и без контакта до конца обычного срока хранения. Телефона, почты, `username` и фото не берём. Кнопка входа на сайте подгружает скрипт telegram.org (он видит адрес посетителя, как при любом обращении к их сайту), только на странице `/account` и только у не вошедших. Диалоги чата на сайте лежат только в `localStorage` браузера. Рассылка: не чаще раза в сутки, днём, не больше пяти событий. В логи бота номера чатов не пишутся. Проверка ссылок и сбор не сохраняют ничего о посетителях. Аккаунты и история посещений: [08](08-аккаунты-и-роли.md).

## Известные пробелы (по убыванию важности)

1. **Туннель** открывает прокси домашнего компьютера всем процессам сервера. Убирается только переездом на зарубежный VPS.
2. **Сайт и мини-приложение не закрыты подпиской**: она действует только в боте. Мини-приложение по прямой ссылке откроется любому.
3. **Лимиты и состояние бота в памяти одного процесса**: при перезапуске сбрасываются, при нескольких экземплярах не суммируются (нужен Redis).
4. **Права модератора не делятся:** любой действительный ключ или аккаунт-модератор может и смотреть, и править (разграничения «просмотр»/«правка» нет); журнал действий есть. Аккаунты и роли: [08](08-аккаунты-и-роли.md).
5. **Нет внешнего мониторинга** и оповещений о сбоях (туннель, бот, сертификат).
6. **Условия использования данных culture.ru** не сверены с юристами: уточнить до публичного запуска.
7. Docker-ограничения и конфиг nginx применены на сервере и проверены по основным сценариям, но полноценного пентеста не было.
8. **Проверка ссылок через прокси** (`AFISHA_USE_PROXY=1`) не привязана к проверенному IP: имя разрешает прокси. По умолчанию прокси выключен и подмена DNS не срабатывает (закрыто 14.11.2026). Загрузчик источников (`Fetcher`) к IP не привязан: он ходит только на разрешённые домены, подмена возможна лишь при захвате DNS самого источника.
9. **Ключи админки лежат открытым текстом** в `.env` (не хешами), добавить администратора можно только правкой файла и пересозданием контейнера.
