# 05. Безопасность

Чтение афиши открыто всем, а часть возможностей стоит денег (запросы к Gemini) или меняет данные (приём событий). Поэтому защита строится вокруг трёх целей: **данные нельзя испортить, сервис нельзя положить, платную модель нельзя сжечь.**

Весь HTTP-слой защиты в одном файле: `app/security.py`. Подключение: `app.middleware("http")(guard)` в `main.py`.

## Кто и что может

| Кто | Что может |
|---|---|
| Любой посетитель | читать события, задавать вопросы ИИ (в пределах лимитов) |
| Чужой сайт (виджет, министерство) | только читать через браузер (CORS: `GET`); виджет подключается без всяких ключей |
| Держатель `ADMIN_API_KEY` | добавлять события и менять статусы |
| Подписчик `@sz_orenteam` | пользоваться ботом |

Ролей, аккаунтов организаторов и входа пользователей нет: админ-методы закрыты одним общим ключом.

## Угрозы и меры

| Угроза | Мера | Где |
|---|---|---|
| Подбор ключа приёма данных | ключ ≥ 24 символов, иначе приём выключен; после 10 неудач адрес блокируется на минуту (даже верный ключ); сравнение за постоянное время по байтам; не-ASCII даёт 401, а не 500 | `main.require_admin`, `security.auth_limiter` |
| Порча базы через API | `javascript:`/`data:`/относительные ссылки отклоняются (только `http(s)`), пределы длины всех полей, пределы цен (≤ 10 млн) и возраста, нормализация мелких ошибок | `schemas.EventIn` |
| Чужая страница тратит квоту ИИ руками посетителей | CORS только `GET`; изменяющие запросы с `Origin` не нашего сайта или `Sec-Fetch-Site: cross-site` получают 403; curl и парсеры (без `Origin`) проходят | `security.cross_site_write`, `main.py` |
| Сжигание квоты Gemini, перегрузка | 20 вопросов/мин с адреса; бюджет модели (4 одновременно, 3000/сутки, 45 с на ответ); сверх бюджета отвечают правила; в боте 8 вопросов/мин и один одновременно на пользователя | `security.LlmBudget`, `agent.ask`, `bot.on_text` |
| Выкачивание и перегрузка API | 300 запросов/мин с адреса; IPv6 считается подсетью /64; `/api/health` вне лимита; плюс лимиты nginx | `security.api_limiter`, `deploy/nginx-afisha.conf` |
| Подмена адреса через `X-Forwarded-For` | берётся последняя запись (добавленная нашим nginx из `$remote_addr`), левые подделываются клиентом; доверие включено только для loopback или при `TRUST_PROXY=1` | `RateLimiter.client_ip` |
| Огромные и «вечные» запросы | тело ≤ 1 МБ (пачка событий ≤ 5 МБ), без `Content-Length` и с `Transfer-Encoding` — 411; таймауты медленных клиентов в nginx | `security.body_too_large`, nginx |
| Тяжёлый поиск | запрос ≤ 200 символов и ≤ 8 слов, `offset` ≤ 100 000, ограничены список статусов и длины фильтров | `main.list_events`, `search.py` |
| XSS | CSP: скрипты только свои и `telegram.org`, **встроенные запрещены**, `object-src 'none'`, `base-uri 'self'`; весь динамический HTML экранируется (`esc`), числа через `Number()`, ссылки только `http(s)`; история чата из `localStorage` проходит очистку формы | `security.CSP_*`, `app.js` |
| Встраивание сайта во фрейм чужой страницы | `frame-ancestors`: только сам сайт и Telegram; для API и `/docs` ещё `X-Frame-Options: DENY` | `security.security_headers` |
| Подмена `Host` | `ALLOWED_HOSTS` (если задан) отклоняет чужие имена (400) | `TrustedHostMiddleware` |
| Утечка версий | `Server: nginx` без версии, `--no-server-header` у uvicorn | nginx, Dockerfile |
| Взлом контейнера | не root (uid 1000), `--read-only` (пишет только `/data` и `/tmp`), `--cap-drop ALL`, `no-new-privileges`, лимит памяти и процессов | `deploy/run.sh`, `Dockerfile` |
| Прочтение секретов на сервере | `.env`, `.env.bot`, база: права 600, каталог данных 700; секреты в образ не попадают (`COPY app`, не весь каталог) | `deploy/run.sh` |
| Инъекции через ИИ | модель получает только инструменты чтения; `event_ids` проверяются на сервере (рекомендовать можно только найденное); описания из источников объявлены данными, а не инструкциями; ответ экранируется везде | `agent.py` |
| Инъекции в бот | данные кнопок разбираются строгими регулярками; названия из источников экранируются в HTML; кнопки под исчезнувшим сообщением не роняют бот; сообщения без автора (от имени канала) подписку не проходят | `bot.py` |
| Вредный ответ источника | общий загрузчик `Fetcher`: только HTTPS и разрешённые хосты (и после перенаправлений), ответ ≤ 8 МБ, `robots.txt` читается перед каждым сайтом, пауза между запросами, капча/403/429 останавливают обход (мы их не обходим). Тексты из разметки очищаются от тегов и сущностей, ссылки только `http(s)` | `sources/base.py`, `sources/jsonld.py` |
| SQL-инъекции | только параметризованные запросы SQLAlchemy; в `LIKE` подставляется нормализованный текст (буквы и цифры) | `search.py`, `normalize.py` |
| Уязвимые зависимости | версии закреплены (`~=`) в `requirements.txt`; на сервере собираются из заранее скачанных колёс | `requirements.txt` |

## Заголовки, которые отдаёт сайт

`Content-Security-Policy` (разная для страниц, `/api/`, `/docs`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (геолокация, камера, микрофон, платежи, USB выключены), `Strict-Transport-Security` (по HTTPS), `Cache-Control: no-store` на `/api/ask`. Проверка: `curl -sI https://195-209-220-227.sslip.io/`.

Страница `/docs` (Swagger) требует `unsafe-inline` и CDN `cdn.jsdelivr.net` — это отдельная более мягкая политика только для неё.

## Персональные данные

Хранятся только данные подписок бота: номер чата Telegram и выбранные город и категория (таблица `subscriptions`). Телефонов, имён и адресов нет. Срок хранения: до `/unsubscribe`, но не дольше 12 месяцев с оформления; при блокировке бота подписки стираются сразу. Диалоги чата на сайте лежат только в `localStorage` браузера. Рассылка: не чаще раза в сутки, днём, не больше пяти событий. В логи бота номера чатов не пишутся.

## Секреты

| Секрет | Где лежит | Заметки |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `.env` локально, `.env.bot` на сервере | выпускает @BotFather; при утечке — перевыпустить командой `/revoke` |
| `GEMINI_API_KEY` | `.env`, `.env.bot` | первый ключ был показан в чате: **удалить его в Google AI Studio**; рабочий ключ создавался отдельно |
| `ADMIN_API_KEY` | `.env` (сейчас не задан: приём данных выключен) | при включении — `secrets.token_urlsafe(32)` |
| SSH-ключ `.pem` | у владельца проекта | вход на сервер, в репозиторий не попадает |

`.env` в `.gitignore`, `.env.example` содержит только имена и описания. Не вставляйте секреты в чаты и тикеты.

## Известные пробелы (по убыванию важности)

1. **Туннель** открывает прокси домашнего компьютера всем процессам сервера. Убирается только переездом на зарубежный VPS.
2. **Сайт и мини-приложение не закрыты подпиской**: она действует только в боте. Мини-приложение по прямой ссылке откроется любому.
3. **Лимиты и состояние бота в памяти одного процесса**: при перезапуске сбрасываются, при нескольких экземплярах не суммируются (нужен Redis).
4. **Один общий ключ** для всех админ-операций, без журнала действий и ролей.
5. **Нет внешнего мониторинга** и оповещений о сбоях (туннель, бот, сертификат).
6. **Условия использования данных culture.ru** не сверены с юристами: уточнить до публичного запуска.
7. Docker-ограничения и конфиг nginx применены на сервере и проверены по основным сценариям, но полноценного пентеста не было.
