# 08. Аккаунты и роли

Сделано 13.11.2026 по требованию владельца проекта: сайт работает без аккаунта, в аккаунте история посещений, роли из ТЗ §3. Код: `app/accounts.py` (логика), `app/api_accounts.py` (методы), `app/auth.py` (доступ модератора), страница `/account` (`app/static/account.*`), миграция `0005`. Тесты: `tests/test_accounts.py` и три теста бота в `tests/test_bot_dispatch.py`.

## Что получилось

1. **Сайт, чат, планировщик, виджет и API работают без входа**, как раньше. Ничего не закрыто за аккаунтом.
2. **Вход только через Telegram, паролей нет.** Две дороги, обе проверяют подпись токеном бота:
   * мини-приложение: кнопка «Войти» в кабинете отправляет `initData` на `POST /api/v1/auth/telegram`;
   * сайт в обычном браузере: кнопка «Войти через Telegram» (виджет telegram.org с `data-auth-url`), Telegram возвращает браузер на `GET /api/v1/auth/telegram/callback/{nonce}`.
3. **Вход живёт в куке `afisha_session`**: `HttpOnly`, `SameSite=Lax`, `Secure` при https, срок `SESSION_DAYS` (30). В базе лежит только SHA-256 токена. Одновременно не больше 10 входов на человека. Выход: `POST /api/v1/auth/logout`.
4. **Что хранится о человеке:** номер Telegram, имя оттуда же, роль, согласие на историю. Телефона, почты, `username` и фото не берём.
5. **История посещений только по согласию.** У нового аккаунта она выключена. Пишется открытие карточки (`/event/{id}`, сервер) и переход по ссылке источника или билетов (`visit.js`, только если история включена), не чаще раза в сутки на карточку, срок `HISTORY_RETENTION_DAYS` (90). Выключение согласия стирает собранное. В кабинете: список, «Очистить», «Скачать мои данные (JSON)», «Удалить аккаунт».
6. **Подписки и сохранённые поиски** привязаны к аккаунту. Подписка из бота и с сайта одна запись: вход привязывает подписки с тем же номером чата (`subscriptions.user_id`). Подписаться можно и из обычного браузера, если вошли через кнопку Telegram (номер аккаунта и есть номер личного чата с ботом).
7. **Роли** (`users.role`):

| Роль | Что получает |
|---|---|
| `user` (Житель, Гость республики: права одинаковые) | кабинет: история, подписки, сохранённые поиски, свои обращения |
| `organizer` | то же, плюс заявки через `/feedback` привязываются к аккаунту: в кабинете статус «Принято / В работе / Обработано» и ответ модератора; ответ приходит ещё и в Telegram от бота |
| `moderator` | всё, что делает `/admin`: очередь, правка, импорт, журнал, сбор, обращения. Вход аккаунтом без ключа; в журнале актор `user:<номер аккаунта>` |
| `ministry` | только чтение: личные ключи для встраивания (`X-Partner-Key`) со своим лимитом запросов в минуту, сводка `/api/v1/ministry/stats` (счётчики, без текстов обращений и без данных людей). Писать ничего не может |

8. **Роли выдаёт только владелец ключа администратора** (`ADMIN_API_KEY` или личный из `ADMIN_USERS`): вкладка «Пользователи и ключи» в `/admin`, `POST /api/v1/admin/users`. Роль можно выдать заранее по номеру Telegram, она дождётся первого входа. «Отозвать доступ»: роль снова `user`, все входы закрыты, личные ключи отозваны. Действия пишутся в журнал изменений. Аккаунт-модератор роли и ключи Министерства выдавать не может.
9. **Ключи для встраивания.** `X-Partner-Key: afk_…`: ключ выпускает министерство в кабинете (до 5 действующих) или администратор (любой лимит до 6000/мин). Показывается один раз, в базе хеш. С ключом запросы на чтение считаются по лимиту ключа, а не по адресу; неверный ключ даёт 401, подбор останавливается тем же лимитом, что и у ключей модераторов.

## Чем сделано иначе, чем в плане

* **Аккаунт удаляется физически**, без `deleted_at`: запись-«надгробие» ничего не даёт, а персональные данные уходят. Номера аккаунтов не используются повторно (`sqlite_autoincrement`), поэтому записи журнала `user:<номер>` не перепутаются с новым человеком.
* **Нет таблицы «сохранённые согласия» и `scopes` у ключей**: согласие хранится в `users.consent_at`, а ключи всегда только для чтения.
* **В мини-приложении аккаунт не создаётся молча**: человек сам нажимает «Войти» в кабинете (`/account`, команда бота `/account`). Согласие на историю отдельный шаг в кабинете, по умолчанию выключено.
* **«Подтверждение ответственным» у организатора не делалось**: роль организатора выдаёт модератор-администратор по заявке.
* **Нужен ответ в Telegram:** его отправляет бот (`send_feedback_replies`, проверка раз в 30 минут), потому что сайт с сервера до Telegram может не дотянуться. Нет бота: ответ виден в кабинете, уведомление ждёт.

## Защита

* Кука `HttpOnly`: скрипт страницы её не читает. Данные входа не кешируются (`Cache-Control: no-store` на `/api/v1/me/*`, `/auth/*`, `/admin/*`, `/ministry/*`).
* Чужие изменяющие запросы с других сайтов отсекает `guard` (`Sec-Fetch-Site`, `Origin`) до кода аккаунтов; отдельно `SameSite=Lax`. Для мини-приложения в веб-версии Telegram (страница во фрейме чужого сайта) при https кука ставится с `SameSite=None`.
* Возврат кнопки входа защищён nonce: адрес содержит случайную строку, которую страница заранее положила в куку. Чужая ссылка с настоящей подписью не войдёт в аккаунт злоумышленника за посетителя.
* Подпись виджета живёт час, мини-приложения сутки. Попытки входа: не больше 20 в минуту с адреса.
* Страница события одинакова для всех, вошедшие и нет: запись истории не меняет ни тело, ни `ETag`, кеш остаётся корректным.
* CSP: скрипт `telegram.org` уже был разрешён, добавлен `frame-src https://oauth.telegram.org` (кнопка входа). Встроенные скрипты по-прежнему запрещены.

## Эксплуатация

* В `.env` **веб-процесса** (не только бота) должны быть `TELEGRAM_BOT_TOKEN` (проверка подписи) и `TELEGRAM_BOT_USERNAME` (имя бота без @, по умолчанию `BashSZbot`). Без токена кабинет показывает «вход не настроен».
* Для кнопки входа в обычном браузере домен сайта привязывают к боту: BotFather → `/setdomain`. `sslip.io` для этого годится, для постоянной работы нужен свой домен. Внутри мини-приложения домен не нужен.
* Бот и сайт должны смотреть в одну базу (так же устроены подписки): иначе ответ модератора не дойдёт до бота.
* Первый модератор: задать `ADMIN_API_KEY`, зайти в `/admin`, вкладка «Пользователи и ключи», выдать роль по номеру Telegram (его видно у @userinfobot). Ключ остаётся аварийным входом.
* Миграция `0005` применяется при старте приложения (таблицы `users`, `user_sessions`, `visit_history`, `saved_searches`, `api_keys`; столбцы `subscriptions.user_id`, `feedback.user_id/reply/replied_at/notified_at`).

## Что не сделано

* **Вход без Telegram** (по ссылке на почту): не делался, нужна отправка писем. Остаётся вопросом к владельцу.
* **Юридический текст.** Согласие и политику обработки данных нужно согласовать с заказчиком (Приложение В ТЗ); сейчас на странице кабинета краткое объяснение, что хранится и сколько.
* **Автотестов интерфейса нет**: кабинет и вкладка «Пользователи» проверены вручную в браузере на временной базе с поддельным токеном бота (вход, история, подписка, сохранённый поиск, роль, ключ, вход модератора без ключа, мобильная вёрстка 375 px). Настоящий вход через кнопку Telegram не проверялся: для него нужен привязанный домен и живой бот.
* **Лимит ключей считается в памяти процесса** (как и остальные лимиты): при нескольких экземплярах не суммируется, при перезапуске сбрасывается. Счётчик запросов ключа пишется в базу пачкой раз в 30 секунд, при падении теряется до 30 секунд.
* **Права модератора не делятся** на «просмотр» и «правку».
* **Уведомления об отменах** (ТЗ §14) на аккаунты пока не завязаны.

## Вход через бота (14.11.2026)

Основной способ входа на сайте в обычном браузере. Не нужны ни виджет telegram.org (в России открывается не всегда), ни привязка домена
в BotFather (`/setdomain`).

1. Кнопка «Войти через Telegram» в кабинете → `POST /api/v1/auth/telegram/bot` → одноразовый код и ссылка `https://t.me/<бот>?start=login_<код>`;
   секрет браузера уходит в куку HttpOnly `afisha_login_req`.
2. Бот (`app/bot.py`, `on_login_link`) показывает кнопки «✅ Войти на сайт» / «✖ Это не я». Номер и имя берутся из самого Telegram.
3. Страница раз в 2 с спрашивает `GET /api/v1/auth/telegram/bot/{код}`: 202 — ждём, 200 — вход выполнен (кука `afisha_session`), 410 — устарело,
   403 — запрос начат в другом браузере. Ссылка живёт 5 минут, забрать вход можно один раз. В базе (`login_requests`) только хеши кода и секрета.

Нужно: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` в `.env` сайта и запущенный бот (на сервере — через туннель, см. docs/04).
Виджет telegram.org остаётся запасным способом под кнопкой.

## Аналитика и рекомендации

* **Кабинет → «Рекомендации для вас»** (`GET /api/v1/me/insights`): профиль интересов из истории посещений (только с согласия), подписок и
  сохранённых поисков; до 6 ближайших событий, которых человек ещё не открывал, с причинами («вы часто выбираете «Театр»», «в городе Уфа»,
  «на площадке, где вы уже бывали»). Нет данных — популярное у посетителей за 30 дней. Код: `app/analytics.py`.
* **Админка → «Аналитика»** (`GET /api/v1/admin/analytics`): аккаунты (всего, новые, активные, с историей, роли), просмотры и переходы к
  билетам за 30 дней, график по дням, популярные события, категории и города, подписки, обращения, ответы помощника.
* **Выгрузка CSV** (`GET /api/v1/admin/analytics/users.csv`, кнопка во вкладке): по строке на аккаунт; разделитель «;», UTF-8 с BOM —
  открывается в Excel без настройки. Номер Telegram не выгружается; ячейки, похожие на формулу, экранируются.
