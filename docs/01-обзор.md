# 01. Обзор

## Задача

Хакатонный кейс: единая достоверная афиша культурных событий Республики Башкортостан. События разбросаны по сайтам театров, музеев и министерства, часто дублируются, а об отменах и переносах узнаёшь на месте. Продукт собирает их в одну базу, склеивает дубли, хранит статус и отвечает на вопросы обычным языком («куда пойти в субботу с ребёнком до 1000 рублей»).

Принцип, на котором держится доверие: **ничего не выдумываем**. Ни ИИ, ни парсер не дописывают то, чего нет в источнике (нет описания, нет статуса, нет цены, так и показываем).

## Что умеет

| Возможность | Где |
|---|---|
| Сайт: поиск и фильтры по дате, городу, цене, возрасту, категориям (несколько сразу) | `app/static/`, `GET /api/events` |
| Чат-помощник с историей диалогов (как ChatGPT), в браузере и в Telegram | `app/static/app.js`, `POST /api/ask`, `app/agent.py` |
| Telegram-бот: меню быстрых фильтров, города, категории, свободный текст | `app/bot.py` |
| Telegram Mini App: тот же сайт внутри Telegram, перестроенный «как приложение» | `app/static/` (режим `.tg`) |
| Статусы: состоится, перенесено, билеты проданы, отменено | поле `status`, `PATCH /api/events/{id}/status` |
| Дедупликация: одно событие из разных источников = одна запись | `app/dedup.py`, `app/ingest.py` |
| Открытый REST API со Swagger | `/docs`, `/openapi.json` |
| Виджет для чужого сайта (министерство) без вмешательства в его системы | `/widget.js`, пример `/widget-demo` |
| Обязательная подписка на канал для пользования ботом | `app/bot.py`, `@sz_orenteam` |
| Подписки на новые события (город и категория, отписка одной командой, не чаще раза в сутки) | `app/subscriptions.py`, `app/bot.py` |
| Источники данных: culture.ru, Яндекс Афиша, Kassir.ru, KudaGo, сайты из `data/sources.json` | `app/sources/`, `python -m app.sync` |
| Пометка «неофициальный сервис» на сайте, в боте, в виджете и в API | `config.DISCLAIMER`, `app/static/` |

## Соответствие требованиям кейса

| Требование | Выполнено |
|---|---|
| Telegram-бот | да, @BashSZbot |
| Веб-сервис с поиском и фильтрами | да |
| Статусы событий | да, отменённые скрыты по умолчанию и перечёркнуты |
| Дедупликация, нет выдуманных мероприятий | да; число подтвердивших источников видно в карточке; демо-данные помечены |
| ИИ-агент: свободный запрос, уточнения, объяснение подборки | да, Gemini с вызовом инструментов, при недоступности режим правил |
| Открытый API и документация | да |
| Виджет на сайт министерства | да |

## Карта файлов

```
afisha/
├── app/
│   ├── main.py          # FastAPI: эндпоинты, страницы, сборка middleware
│   ├── security.py      # лимиты, заголовки безопасности, проверки запроса, бюджет ИИ
│   ├── config.py        # все настройки из окружения и .env
│   ├── models.py, db.py # таблица events, подключение к БД
│   ├── schemas.py       # pydantic: вход события, ответы API, проверка ссылок и размеров
│   ├── normalize.py     # категории, статусы, города, нормализация текста, возраст
│   ├── dedup.py         # поиск дубля и ключ склейки
│   ├── dedup_audit.py   # пары, оставшиеся после склейки: python -m app.dedup_audit
│   ├── ingest.py        # создание/слияние события, загрузка из JSON/CSV
│   ├── search.py        # единый поиск для API, бота и агента
│   ├── formatting.py    # цена, дата, карточка для чата, сериализация в API
│   ├── agent.py         # ИИ-агент: Gemini + режим правил
│   ├── rules.py         # разбор запроса регулярками (запасной режим)
│   ├── bot.py           # Telegram-бот
│   ├── maintenance.py   # служебные операции: исправление серий показов, удаление демо-событий
│   ├── subscriptions.py # подписки на новые события: добавление, подборки, срок хранения
│   ├── sync.py          # CLI синхронизации с источниками
│   ├── sources/         # адаптеры culture_ru, yandex_afisha, kassir, kudago, sites; base.py (загрузчик), jsonld.py (schema.org)
│   └── static/          # index.html, tailwind.css (собранный), app.js, boot.js, widget.js, widget-demo.*
├── frontend/tailwind.css  # вход для Tailwind; tailwind.config.js рядом с проектом: токены дизайна и анимации
├── tests/               # 270 тестов; tests/demo_data.py — выдуманные данные только для тестов
├── data/sample_events.json   # 120 реальных событий для запуска «с нуля»
├── scripts/export_sample.py  # выгрузка такого набора из своей базы
├── deploy/              # run.sh (запуск контейнеров), nginx-afisha.conf
├── docs/                # эта база знаний
├── Dockerfile, docker-compose.yml, requirements.txt, requirements-dev.txt  # deploy/Dockerfile.offline — серверная сборка без PyPI
├── .env.example         # образец настроек (секретов нет)
└── afisha.db            # локальная база (в git не кладётся)
```

## Состояние данных

* Локальная база на 13.11.2026: 761 событие из трёх источников (Яндекс Афиша 389, Kassir.ru 252, culture.ru 200 записей-источников),
  79 событий подтверждены двумя источниками. Демо-данных нет: выдуманные события живут только в `tests/`.
* Города: Уфа (673), Стерлитамак (29), Салават (16) и ещё 14 значений, из них 6 — названия районов («Гафурийский район»).
* Серии показов (48 событий из Kassir.ru) хранят известную дату показа и конец серии (`series_until`), см. `docs/02`.
* Описания нет у половины событий, статусы отмен и переносов в данных не встречались: все события «состоится».
* Подробное сравнение с ТЗ и список недоделок: [upd.md](../upd.md).
