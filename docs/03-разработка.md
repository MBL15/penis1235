# 03. Разработка

## Запуск в Docker (без Python и Node)

```bash
docker compose up --build
```

Сайт и API: http://localhost:8000. Бот: `docker compose --profile bot up --build` (нужен `TELEGRAM_BOT_TOKEN` в `.env`). Сбор по расписанию: `docker compose --profile sync up` (источники должны открываться с этой машины). При первом запуске подгружается `data/sample_events.json` (реальные события), порт меняется `WEB_PORT`, загрузка набора отключается `LOAD_SAMPLE_DATA=0`. Колёса зависимостей (`deploy/Dockerfile.offline`) нужны только серверу без PyPI.

## Запуск локально (Windows, PowerShell)

```powershell
cd afisha
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
copy .env.example .env                              # впишите ключи, если нужны
.\.venv\Scripts\python.exe -m app.ingest data\sample_events.json   # 140 записей из трёх источников (или загрузите свои, см. ниже)
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

* Сайт http://localhost:8000, API http://localhost:8000/docs, виджет http://localhost:8000/widget-demo.
* Бот: `.\.venv\Scripts\python.exe -m app.bot` (нужен `TELEGRAM_BOT_TOKEN`).
* В Claude Code запуск сайта описан в `C:\Users\matve\102\.claude\launch.json` (конфигурация `afisha`, порт 8000).
* В Git Bash команда `python` может оказаться заглушкой Microsoft Store: используйте `.venv/Scripts/python.exe`.

| `HTTPS_PROXY`, `NO_PROXY` | прокси для запросов к Gemini (читает SDK) | из окружения |

| `LLM_MAX_CONCURRENCY`, `LLM_DAILY_LIMIT`, `LLM_TIME_BUDGET` | бюджет ИИ: одновременно / в сутки (0 = без лимита) / секунд на ответ | 4 / 3000 / 45 |

Файл `.env` в `.gitignore`. Сгенерировать ключ приёма: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

### Где взять ключи

* **Gemini**: https://aistudio.google.com/apikey (нужен вход в Google и принятие условий). Модели 2.5 новым ключам закрыты, `-latest` доступен не всем: список своих моделей даёт `client.models.list()`.
* **Groq**: https://console.groq.com/keys (вход через Google или GitHub; бесплатный тариф ограничен 8000 токенов в минуту, один ответ тянет 5–6 тысяч, поэтому Groq годится как запасной провайдер, а не основной). Список доступных вашему ключу моделей: `GET {GROQ_BASE_URL}/models`; `llama-3.3-70b-versatile` недоступна, используется `openai/gpt-oss-20b`.
* **Ключ админки и ключи модераторов** никто не выдаёт: придумайте сами (`secrets.token_urlsafe(32)`) и запишите в `.env`; на сервере после правки пересоздайте контейнер.
* **Тариф для расчёта стоимости ответа**: `LLM_PRICE_INPUT_RUB_PER_M`, `LLM_PRICE_OUTPUT_RUB_PER_M` (см. README, «Стоимость ответа»).
* **Бот**: @BotFather. Бота нужно **назначить администратором канала**, на который требуется подписка.

Яндекс Афиша обходит страницы событий медленно (пауза 1,2 с): 150 страниц около 5 минут. Список адресов берётся из sitemap и кэшируется на сутки. Свой сайт со schema.org добавляется в `data/sources.json` (формат в `app/sources/sites.py`).

Остальное:

```powershell
.\.venv\Scripts\python.exe -m app.sync culture-ru --dry-run            # посмотреть, что загрузится
.\.venv\Scripts\python.exe -m app.sync culture-ru --pages 10            # ~200 ближайших событий
.\.venv\Scripts\python.exe -m app.sync culture-ru --pages 10 --drop-demo # то же и убрать демо-события
.\.venv\Scripts\python.exe -m app.ingest events.json                     # или events.csv
.\.venv\Scripts\python.exe -m app.maintenance demo-reset --apply         # удалить только демо-события (если они попали в базу)
```

Повторный запуск безопасен: события обновляются по ссылке, а не дублируются. Формат записи для JSON/CSV: `title`, `start_at`, `source` (обязательны); `description`, `category`, `city`, `venue`, `address`, `end_at`, `price_min`, `price_max` (0 = бесплатно, пусто = неизвестно), `age_limit` (`12` или `"12+"`), `kids_friendly`, `url`, `image_url`, `status`.

`url`, `image_url`, `source_url` принимаются только с `http://` или `https://`. Мелкие ошибки источника (конец раньше начала, цены местами) чинятся, а не отклоняют запись.

### Администрирование, логи, метрики

* Админ-страница `/admin` открывается ключом из `ADMIN_API_KEY` или `ADMIN_USERS=имя:ключ` (ключи ≥ 24 символов): `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
* Логи по умолчанию JSON; для чтения глазами `LOG_FORMAT=text`. Метрики: `curl http://localhost:8000/metrics`.
* Схема базы меняется **миграциями Alembic** (`migrations/versions/`): `python -m alembic revision -m "что меняем"`, миграция должна быть повторяемой («если столбца нет»), при старте `init_db` применяет всё сам. Значения для старых строк заполняйте в `db.backfill_defaults`. Руками: `python -m alembic upgrade head`, `python -m alembic current`.
* Новая страница на сервере собирается в `app/pages.py` без шаблонизатора; Tailwind просматривает этот файл, поэтому после правки классов запустите `npm run build:css`.
* Страница «Выходной день» собирается в `app/plan_page.py`; Tailwind просматривает и его (`tailwind.config.js`).

## Как расширять

### Новый источник данных
1. Адаптер в `app/sources/`: функция `fetch_records(...)`, отдающая записи в формате `EventIn`. Загрузку делать только через `Fetcher` (`app/sources/base.py`): он сам читает robots.txt, делает паузы, не выходит за разрешённые хосты и останавливается на капче. Разметку schema.org разбирает `jsonld.record_from_ld`. Если у сайта несколько дат на одной странице, давать каждой дате свой адрес (`url#дата`).
2. Подключить в `app/sync.py` (список `SOURCES` и `producers()`).
3. Нормализация, дедупликация и статусы уже готовы: адаптер их не трогает.

### Новая категория
Добавить в `CATEGORIES` и `CATEGORY_STEMS` (`normalize.py`), иконку `i-<slug>` в спрайт `app/static/index.html`, цвет плитки в `TONES` (`tailwind.config.js`), описание в `CATS` (`app.js`), затем `npm run build:css`. Подсказка модели строится из `CATEGORIES` сама.

### Новый город
Добавить в `CITY_FORMS` (`normalize.py`) формы слова (корни без окончаний). Неизвестный город не теряется, остаётся как есть.

### Правка поведения ИИ
Общий слой интерфейса (`app/static/ui.css`, `ui.js`, подключены на всех страницах кроме `/admin`): нижняя панель разделов (Афиша, Помощник, Выходной, Кабинет, Связь; на главной в широком окне скрыта, там есть верхняя), уведомления `ui.toast`, индикатор загрузки на кнопках `ui.busy`, кнопки «Следить» и «Поделиться» на карточке события (`data-follow`, `data-share`), плавный переход между страницами (View Transitions), заглушки загрузки. Правило: любое действие не дальше трёх нажатий. Все движения отключаются при «уменьшить движение». Ссылка `/?chat=1` открывает чат.

Системный промпт: `build_system_prompt` в `agent_prompt.py`; **при каждой правке меняйте `PROMPT_VERSION`**: версия пишется в трассу и в отчёт прогона. Инструменты: `agent_tools.py` (`TOOLS`). Правила режима без модели: `rules.py`. После правки:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m eval.run --mode rules          # метрики запасного режима, отчёт в eval/reports/
.\.venv\Scripts\python.exe -m eval.run --mode llm --confirm-spend   # настоящая модель: тратит квоту и деньги, нужен ключ
```

Тесты подменяют модель, поэтому поведение живой модели видно только прогоном `--mode llm`. Если по результатам прогона вы исправляете агент, отложенные запросы (`eval/holdout.json`) перестают быть отложенными: заведите новые.

## Фронтенд: Tailwind CSS

Стили собираются Tailwind CSS 3.4 из разметки и скриптов. Node нужен **только разработчику**, на сервере и в Docker его нет.

```powershell
npm install                 # один раз: ставит Tailwind
npm run build:css           # пересобрать app/static/tailwind.css (после любой правки классов)
npm run watch:css           # пересобирать при сохранении
```

* Классы пишутся прямо в `app/static/index.html` и в шаблонах `app/static/app.js`. Tailwind ищет их в тексте **целиком**, поэтому строку класса нельзя собирать из кусков (`'tg:' + name`): такой класс не попадёт в CSS. Исключение: `tone-*` собираются из слага категории и поэтому внесены в `safelist` конфига.
* В классах внутри `app.js` нельзя использовать двойные кавычки (`after:content-["x"]` обрывает атрибут `class`): пишите `after:content-['x']` внутри строки в обратных кавычках. Тест `test_frontend.py` это проверяет.
* Готовый `app/static/tailwind.css` коммитится: забыли пересобрать, и новые классы не заработают. Дизайн-токены (цвета, тени, радиусы, кривые анимаций) правятся в `tailwind.config.js`, а не в разметке.
* Имена теней не должны совпадать с именами цветов темы (`shadow-glass` стал бы ещё и цветом тени), поэтому они называются `shadow-surface`, `shadow-cta`, `shadow-selected`.
* Ключевые кадры, на которые ссылается только составной класс плагина (`grow` в `scroll-progress`), Tailwind сам не добавляет: они вынесены в `addBase`. Тест проверяет, что все кадры на месте.

## Соглашения

* Комментарии и тексты интерфейса на русском; имена в коде на английском.
* Весь HTML, собираемый в JS, экранируется через `esc()`, числа из API проходят `Number()`. Встроенных скриптов и обработчиков `on…=` в страницах быть не должно (CSP их заблокирует, тест `test_pages_have_no_inline_scripts_or_handlers` следит).
* Анимации: только `transform`/`opacity`, без `blur`-фильтров и бесконечных петель; уважать `prefers-reduced-motion`.
* Стили только утилитами Tailwind; в разметке допустим лишь `style="--i:N"` (порядок появления).
* Любое новое поле `EventIn` получает предел длины или значений.
